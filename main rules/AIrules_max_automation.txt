# 최대 자동화 운영 규칙 (결론)

- 모든 작업의 1순위 목적은 **최대의 자동화**.
- 보안/결제/권한/치명적 데이터 손실 위험이 아닌 한 사용자 확인 없이 직접 처리.
- 사용자 요청이 모호해도, 실행 가능한 최선의 자동화 경로를 먼저 수행하고 결과 보고.

## 사용자 질문/확인 메시지 형식

- `[done]`은 모든 작업이 문제 없이 전부 완료된 **최종 마지막 응답**에서만 문장 맨 앞에 사용.
- 중간에 사용자 확인/요청이 필요하면 문장 맨 앞에 `[check]` 사용.
- 중간에 잘못된 점/실패가 발생하면 문장 맨 앞에 `[error]` 사용.
- 질문 자체가 이해되지 않거나 처음부터 불가능하면 문장 맨 앞에 `[no]` 사용.
- 기술적으로 명시적인 한계가 있으면 문장 맨 앞에 `[limit]` 사용.
- 원래 Cursor/Google Cloud 목적상 되어야 하는 동작이 안 되는 버그면 문장 맨 앞에 `[bug]` 사용.
- 위 분류에 포함되지 않으면 문장 맨 앞에 `[?+문제점의 영어단어화]` 형식 사용.
- 상태 접두어를 붙일 때는 왜 그렇게 판단했는지 이유를 반드시 포함.

## 운영 기본 원칙

- 가능하면 같은 턴에 구현+검증+커밋+푸시까지 끝낸다.
- 반복 수작업은 스크립트/에이전트/대시보드 자동화로 전환한다.
- 같은 종류의 수동 확인 요청은 규칙화하여 이후 자동 적용한다.
