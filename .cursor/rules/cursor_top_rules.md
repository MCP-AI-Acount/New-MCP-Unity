# Cursor 최상위 규칙

여기에 규칙을 작성하세요. 웹에서 저장하면 서버의 이 파일에 반영됩니다.

## 대시보드 동기화 고정 규칙

- 밴다이어그램(명령 프로세스) 또는 중요 제한점(기기별/클라우드별 제한)을 수정할 때는 아래 2개를 반드시 함께 수정한다.
  - `web-browser/static/index.html`
  - `web-browser/static/app.js`
- 스타일 변경이 필요하면 `web-browser/static/styles.css`도 함께 수정한다.
- 위 내용 수정 후에는 웹 브라우저 대시보드가 즉시 반영되도록, 같은 작업 턴에서 서버/정적 파일 변경을 완료 상태로 커밋한다.

## 자동화 우선 운영 규칙

- 모든 코드/설정/배포/동기화 작업은 기본적으로 **최대의 자동화**를 목표로 처리한다.
- 보안/결제/권한/파괴적 변경(데이터 삭제, 비가역 작업)처럼 중요한 경우를 제외하고는 사용자에게 중간 확인을 요구하지 않고 직접 진행한다.

## 스크립트 파일명 접두어 규칙

- 사용자가 직접 만들어달라고 지시한 명령 스크립트: `_scriptname.py`
- AI가 필수라고 판단해 만든 스크립트: `__scriptname.py`
- 필요하지만 패치/버전업으로 삭제 가능성이 있는 스크립트: `___scriptname.py`
- 테스트 스크립트: `_____scriptname.py`

## 사용자 응답 접두어 규칙 (정의)

- `[done]` : 끝까지 전부 이상없이 완료했어. (최종 마지막 응답에서만 사용)
- `[check]` : 중간에 사용자 확인이나 추가 요청이 필요해.
- `[error]` : 중간에 작업이 잘못됐거나 실패가 발생했어.
- `[no]` : 처음부터 실행이 안 되거나 질문 자체를 이해할 수 없어.
- `[can’t]` : 현재 기술 스택(커서3/구글클라우드런/깃허브) 지원 범위 밖이라 불가능해.
- `[don’t]` : 기술적으로는 가능하지만 지금 짜놓은 구조/설정 때문에 불가능해.
- `[bug]` : 원래 Cursor/Google Cloud 목적상 되어야 하는 동작이 안 되는 버그 상황이야.
- `[?+영어문제단어]` : 위 범주 어디에도 정확히 안 들어가는 예외 상황이야.
